1. What we are building

A help icon in the Net Net top bar opens a right-side panel over whatever the user was doing. The panel has one search box and a three-way switcher.

  • Chat is Crisp's AI agent. It answers from the help center and hands off to a real person on defined rules. It already knows who the user is.
  • Watch is video answers, playing inside the panel.
  • Read is the written help center.

The user types once. All three views respond to the same query.

2. The architecture, and why

The core decision

There is exactly one knowledge base. Watch and Read are two filtered views of the same 66 articles at help.netnet.app. There is no second knowledge base, no second Crisp workspace, and no duplicated video articles.

This was not the obvious answer, so here is why the alternatives were rejected. All three were tested, not assumed.

OptionVerdictReason
Second helpdesk on the same websiteImpossibleEvery one of Crisp's 29 helpdesk API paths is singular. There is no helpdesk_id segment anywhere in the API.
Second Crisp workspace for videoRejectedCrisp bills per workspace. Adds $95 to $295 a month, its own seats, and a second separately trained and separately billed AI agent. No cross-search between the two.
A spare locale used as a "Video" pseudo-KBRejectedLocales are a fixed enum of 42 real languages. You would have to pick something like English (UK), it appears in the visitor-facing language picker as that language, and it emits incorrect hreflang.
A "Video" category, filtered at search timeDoes not workTested directly: passing &category={id} to Crisp's search returns byte-identical results. Crisp search cannot be scoped by category, and there is no tag field on articles.

So the split happens on Net Net's side, not Crisp's. Net Net asks Crisp for ranked results, then decides how to present them. Because Net Net can see each article's raw content, it can detect video structurally rather than relying on anyone remembering to tag something. That is the whole trick, and it is described in section 7.

5. Identity handshake Andrés Arthur

Net Net already pushes some user data into Crisp. Live conversations show a payload of company_name, start_date, user_id, is_owner, is_admin, is_lead, is_user, is_superadmin. That is good, and it is currently unsigned, which means any browser can claim to be any customer. Signing it is the first job.

Backend: sign the email

HMAC-SHA256 over the email address string, keyed with the workspace secret. Crisp is emphatic that no other digest is accepted. Expose it on whatever endpoint already hydrates the session; do not create a round trip just for this.

// Node, illustrative
const crypto = require("crypto");
const signature = crypto
  .createHmac("sha256", process.env.CRISP_IDENTITY_SECRET)
  .update(user.email)
  .digest("hex");

// returned with the session payload
{ crispEmail: user.email, crispSignature: signature }

Frontend: push it

The signature is the second element of the user:email array, not a separate key. This trips people up.

$crisp.push(["set", "user:email",    [session.crispEmail, session.crispSignature]]);
$crisp.push(["set", "user:nickname", [user.fullName]]);
$crisp.push(["set", "user:avatar",   [user.avatarUrl]]);
$crisp.push(["set", "user:company",  [workspace.name, { url: workspace.domain }]]);

$crisp.push(["set", "session:data", [[
  ["user_id",       user.id],
  ["workspace_id",  workspace.id],
  ["role",          user.role],          // Owner | Admin | Lead | Member
  ["plan",          workspace.plan],
  ["seats",         workspace.seatCount],
  ["signed_up",     workspace.createdAt],
  ["app_version",   BUILD_VERSION],
  ["current_route", router.currentRoute] // see section 13
]]]);

$crisp.push(["set", "session:segments", [[user.role.toLowerCase(), workspace.plan]]]);

Values must be strings, numbers, or booleans, and Crisp caps each at 200 characters.

Why the role matters

Net Net's four roles see genuinely different products. Reports are Owner and Admin only. Leads cannot retag other people's messages. If the agent does not know the role, it will send a Member hunting for a button they cannot see. Pushing role is not a nice-to-have.

6. Backend: the help API Andrés

Three endpoints. All server-side, all holding the Crisp credentials.

6.1 GET /api/help/articles

Proxies and caches Crisp's article list, adding the video flag. Source endpoint:

GET https://api.crisp.chat/v1/website/{website_id}/helpdesk/locale/en-us/articles/{page}

Paginated. 66 articles is a handful of pages. Cache the assembled result for 15 minutes. Response shape:

[{
  "id":          "b711b74b-...",
  "title":       "Running Retainers",
  "description": "A Retainer Job runs in monthly cycles...",
  "url":         "https://help.netnet.app/en-us/article/running-retainers-sme359/",
  "category":    "Jobs",
  "featured":    false,
  "video":       { "provider": "youtube", "id": "dQw4w9WgXcQ" }  // or null
}]

6.2 GET /api/help/search?q=

See section 8. Returns the same object shape, ranked.

6.3 GET /api/help/article/:id

Full article content, for the in-panel reader if and when we build it. Phase 2.

Non-negotiable

The Crisp API token and the identity secret live in environment config on the server. Neither appears in client bundles, in a public route, or in a browser network request. If the panel needs Crisp data, it asks Net Net, and Net Net asks Crisp.

7. Video detection Andrés

Crisp has no tag field, no custom metadata, and no article type. The only writable fields are title, content, description, slug, category and section. So we cannot mark an article as "video" in Crisp.

We do not need to. Crisp's article content comes back as raw Crisp Markdown, and video embeds use distinctive tokens. Scan for them.

const VIDEO = [
  { provider: "youtube",     re: /\$\{youtube\}\[[^\]]*\]\(([^)]+)\)/ },
  { provider: "vimeo",       re: /\$\{vimeo\}\[[^\]]*\]\(([^)]+)\)/ },
  { provider: "dailymotion", re: /\$\{dailymotion\}\[[^\]]*\]\(([^)]+)\)/ },
  { provider: "frame",       re: /\$\{frame\}\[[^\]]*\]\(([^)]+)\)/ }   // Loom, Wistia
];

function detectVideo(content) {
  for (const v of VIDEO) {
    const m = content.match(v.re);
    if (m) return { provider: v.provider, id: m[1] };
  }
  return null;
}
Why this beats a naming convention

Nobody has to remember to tag anything. The moment Marc drops a video into an article, that article appears in Watch. The moment he removes it, it leaves. The content is the metadata, so it can never drift out of sync.

The first match wins. If an article carries more than one video, Watch shows it once and the rest are visible when the user opens the article. Good enough for now; revisit if multi-video articles become common.

8. Search Andrés

The one real fragility in this design

Crisp's REST API has no search endpoint. Grepping the entire v1 reference returns zero search, suggest, or query paths. The endpoint we are using is the one Crisp's own help center search box calls, and it is undocumented and unversioned. Treat it as breakable and ship the fallback in the same release.

Primary

GET https://help.netnet.app/en-us/includes/search/?query={term}

Verified live on August 1, 2026. Unauthenticated, HTTP 200, returns ranked results as an HTML fragment: a <ul> of csh-include-search-result items, each carrying article title, article URL, and the article's description as the snippet.

  • The parameter must be query. ?q= returns HTTP 400 "Invalid data received."
  • Parse server-side, return JSON, merge in the video flag by matching URL against the cached article list.
  • Cache each query for 5 minutes. Debounce on the client at 250ms so typing does not hammer it.

Fallback, shipped from day one

If the primary returns anything other than a 200 with parseable results, fall back to token matching over the cached article list: score title matches highest, then description, then category. Roughly thirty lines. Log the fallback so we notice if Crisp changes the endpoint.

Ranking note

The snippet in results is literally the article's description field, confirmed character for character. That field is nullable and is not auto-generated. Any article without one shows an empty snippet. There is at least one today: "How to Cancel Your Subscription." Filling these in is content work, not engineering work, but it is a launch blocker for Read and Watch looking finished.

10. Chat tab Arthur

Verified, and it changes the design

Crisp's chatbox cannot be mounted as a child of one of our div elements. There is no container, mount, or target option in the SDK. container:index is a z-index, nothing more. And a fully custom chat UI is not merely unsupported, it is impossible: Crisp has no visitor-side authentication, only operator and plugin tokens, so building our own frontend would mean shipping an operator token to the browser.

What Crisp does support, in an article published July 27, 2026, is embedding the chatbox in an iframe. That is the method we use.

Implementation

Use Crisp's Advanced method, a self-hosted page, not the simple go.crisp.chat link. The simple link cannot carry a signed identity or session data, which we need.

  1. Host https://netnet.app/help/chat-frame. A blank page whose only job is to run Crisp.
  2. Set the runtime config before the Crisp script loads: 
    window.CRISP_RUNTIME_CONFIG = {
  lock_maximized:     true,   // cannot be collapsed
  lock_full_view:     true,   // fills the frame
  cross_origin_cookies: true
};
  3. Inside the frame, run the full identity push from section 5.
  4. In the panel, render <iframe src="/help/chat-frame"> filling the Chat tab's area.
  5. Do not load Crisp on the parent page at all. Crisp warns that installing both methods shows the visitor two chatboxes. Loading it only inside the frame avoids the problem entirely and keeps the floating bubble off every Net Net screen.

The postMessage bridge

Because Crisp lives in the frame, the parent cannot call $crisp directly. Self-hosting the frame on our own domain means we control both sides, so relay what the panel needs:

DirectionMessagePurpose
frame → parent{type:"unread", count:n}Drives the help icon badge. Frame listens to $crisp.push(["on","message:received",...]).
frame → parent{type:"escalated"}Panel can show that a human has joined.
parent → frame{type:"ask", text:"..."}Sends the search box query into the conversation. Frame calls $crisp.push(["do","message:send",["text", text]]).
parent → frame{type:"context", route:"..."}Updates session:data.current_route on navigation. See section 13.

Validate event.origin on both sides. Do not use "*" as the target origin.

Styling reality

The chatbox interior is Crisp's, and it stays Crisp's. Available controls are the complete list: color:theme (use purple), color:mode (mirror Net Net's light and dark setting), layout:theme, tile, and position:reverse. There is no supported CSS injection for the chatbox. CSS overrides against Crisp's DOM do technically work, because the widget renders as in-page DOM rather than a shadow root, but the class names are generated and change between Crisp releases. Do not build on that. Accept the seam for v1.

11. Watch tab Arthur

Entirely Net Net's UI. Crisp is only the data source, so we have full control here.

  • Idle, no query: heading "Most watched", show featured video articles.
  • With a query: the ranked results from /api/help/search, filtered to video !== null.
  • Card: 16:9 thumbnail, duration badge, title, description snippet with the query terms highlighted.
  • Play: the card expands in place and the player replaces the thumbnail. Playback happens inside the panel. Nobody leaves Net Net to watch a help video.
  • Player: build the embed URL from the detected provider and id. YouTube youtube-nocookie.com/embed/{id}, Vimeo player.vimeo.com/video/{id}, frame provider uses the captured URL as-is.
  • Below the player: a link to the full article, because the video lives inside a written article that has more detail.
  • Empty state: "No video covers that one yet. Check Read for the written answer." with a one-tap switch to Read. This state will be common at launch and should not feel like a dead end.
Thumbnails

Provider thumbnails (YouTube's i.ytimg.com) are the cheapest path and are fine for v1. If we want on-brand thumbnails later, they would come from the screen library rather than from the video host. Per Marc's standing rule, any Net Net-authored thumbnail is SVG, not PNG.

12. Read tab Arthur

  • Idle: browse by category. The ten categories are Me, Jobs, Quick Tasks, Sales, Contacts, Chat, Performance, Settings, My Profile, Using AI.
  • With a query: ranked results, title plus description snippet, query terms highlighted.
  • Video marker: results that also have a video carry a small "Has video" marker, so the two tabs feel connected rather than separate.
  • Click behavior, v1: open help.netnet.app in a new tab.
Why not render articles in the panel for v1

Crisp content is Crisp-flavored Markdown, not standard Markdown. It has custom callout syntax (|, ||, |||) and the ${provider} embed tokens. A stock renderer will mangle it. Rendering in-panel means writing a small Crisp-Markdown shim, which is real work and belongs in phase 2, not in the release that proves the idea.

One known content bug to be aware of when that shim gets written: the fenced callout form renders broken in Crisp itself. Only the single-line || body form is safe.

13. Contextual help API Arthur

The highest-value thing this architecture unlocks, and it is nearly free once the panel exists. Expose a global:

NetNet.help.open({ query: "retainer cycle", tab: "watch" });

Then any confusing surface in the product can hand the user straight to the answer. A question mark beside the Retainer cycle selector opens help already searched. An empty Performance tab links to the article that explains what will appear there. An error toast offers "what does this mean?" that opens Chat with the error already typed.

Two supporting requirements:

  • Push the current route into session:data.current_route on every navigation, via the postMessage bridge. The agent then knows the user is on the Jobs Performance tab when they say "this number looks wrong," and so does the operator when it escalates.
  • Support a URL parameter, ?help=retainer, so links in emails and release notes can open the panel pre-searched.

14. Accessibility and mobile Arthur

  • Panel is role="dialog" with aria-modal="true" and an accessible name.
  • Focus moves to the search input on open, is trapped inside the panel while open, and returns to the help icon on close.
  • The switcher is a real tablist: role="tablist", role="tab", aria-selected, arrow-key navigation between tabs.
  • Result counts are announced. Wrap the results region in aria-live="polite".
  • Video players carry a title attribute naming the article.
  • Below 620px the panel is full width and full height, with the search box and switcher pinned at the top.
  • All interactive targets are at least 44px on touch.
  • Respect prefers-reduced-motion: no slide, just a fade.

16. Phasing

Phase 1, the proof

  • Identity signing on, unsigned payload retired
  • /api/help/articles and /api/help/search with the fallback
  • Panel shell, search, switcher, Read tab linking out
  • Chat tab via the self-hosted iframe

This is shippable without a single video existing, and it is already better than the status quo.

Phase 2, Watch becomes real

  • Video detection and the Watch tab
  • In-panel playback
  • NetNet.help.open() and the first contextual entry points

Gated on content, not on engineering. Watch ships when there are videos to put in it.

Phase 3, polish

  • In-panel article rendering with the Crisp-Markdown shim
  • Route context in session:data
  • Hugo Widget Tools, letting the agent navigate the app for the user rather than describing where to click scope not yet assessed

17. Acceptance criteria

  • Help icon appears on every authenticated route and opens the panel in under 300ms.
  • A logged-in user's email, name, company, role, and workspace appear in the Crisp inbox with a verified identity badge, not just as text.
  • No Crisp token or signing secret appears in any client bundle or browser network request.
  • Typing a query updates Watch and Read counts within 500ms of the debounce firing.
  • Killing the includes/search endpoint in a test still returns sensible ranked results from the fallback, and logs that it fell back.
  • An article with a YouTube embed appears in Watch, and removing the embed removes it from Watch within the 15 minute cache window, with no other change.
  • A video plays to completion inside the panel without navigating away.
  • Only one chatbox is ever visible. No floating bubble appears on any Net Net screen.
  • Asking the agent for a human results in a real handoff, and the operator sees the user's identity without asking for it.
  • Panel is fully operable by keyboard alone, and Escape closes it from any tab.
  • At 375px wide the panel is usable and nothing is clipped.
  • Light and dark both look intentional, including the Crisp frame.

18. Open decisions

  1. Agent name. Zimmer throughout the mockup, as Marc's placeholder. Sarah is taken by the OpenClaw sub-agent and must not be reused. Final name pending.
  2. Does the panel replace the existing floating chatbox everywhere, immediately? Recommendation: yes. Two entry points to support is worse than one, and the floating bubble is the thing the panel is meant to improve on.
  3. Video hosting. YouTube is cheapest and gives free thumbnails, but puts Net Net help content on a public YouTube channel with related-video surface area. Vimeo or Wistia cost money and keep it contained. This decision blocks nothing in phase 1 but should be settled before the first video is recorded, because moving hosts later means re-embedding every article.
  4. Does Read stay a link-out, or become in-panel? Phase 1 links out. Worth revisiting once we see whether people bounce.
  5. Crisp plan tier. The helpdesk requires Essentials or above and the MCP is listed under Plus, so Net Net appears to be on Plus, but plan tier is not readable through the API. Marc to confirm, because the AI agent's included credit allowance depends on it.
